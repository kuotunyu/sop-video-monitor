# reports/

Every run directory under `reports/` is self-describing and recomputable from what is committed:

| file | what it is | regenerated by |
|---|---|---|
| `data_audit.json` | what was actually probed on disk (videos, fps, frame counts, label alignment, HA-ViD inventory) | `sop-monitor audit-industreal` |
| `config.json` | dataset, split, feature extractor (model, weights SHA-256), head, selected hyper-parameters, runtime | `sop-monitor train-baseline` |
| `predictions_<split>.csv` | the real per-frame model outputs next to the ground truth (`-1` = background) | `sop-monitor train-baseline` |
| `metrics.json` | spec 4.2 metrics per run with participant-bootstrap CIs, per-video numbers, confusions | `sop-monitor score-predictions --run <dir>` (no data, no GPU) |
| `tables.md` | markdown tables rendered from `metrics.json` + `config.json` | `sop-monitor score-predictions --run <dir> --write` |
| `README.md` | the human-written report: identity, definitions, results, failure cases, cost, blockers | by hand |

`sop-monitor reproduce-lite` (what CI runs) recomputes `metrics.json` from every committed
`predictions_*.csv` and fails if the numbers or `tables.md` drift.

## Three tiers, never mixed

| tier | directory prefix | meaning |
|---|---|---|
| **engineering smoke** | `smoke_*` | proves a code path runs (synthetic clips, a handful of frames); numbers are meaningless and must not be quoted |
| **development result** | `*_dev_*` | real data, real model outputs, but evaluated on the *validation* split that was also used for model selection; useful for iterating, not a headline |
| **formal research result** | `*_test_*` (none yet) | one-shot evaluation on the frozen, participant-disjoint test split whose hash is committed under `splits/`; only after the protocol is fixed on val |

Current contents:

- `industreal_dev_v1/` — development result. IndustReal is the metric-donor dataset (spec 3.1);
  its numbers never enter an HA-ViD table. No formal result exists yet because no HA-ViD video
  or annotation is on disk (see `industreal_dev_v1/data_audit.json`).
